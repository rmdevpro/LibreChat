The most likely cause for this issue is that `agent_id` (and potentially other critical fields like `provider` and `model`) are being "lost" or becoming `undefined` when the `AdvancedPanel` is active. 

In `react-hook-form` (v7+), fields registered via `Controller` or `register` are **unregistered when they unmount** unless `shouldUnregister: false` is explicitly set in `useForm`. Since `AgentConfig` (which contains the `id`, `name`, `provider`, and `model` fields) is unmounted when switching to the `AdvancedPanel`, these fields are being removed from the form state that `handleSubmit` passes to `onSubmit`.

When `agent_id` becomes `undefined`:
1. `onSubmit` skips the `if (agent_id)` block.
2. It falls through to the "Create" logic.
3. Because `provider` and `model` are also in unmounted components, they are likely `undefined` as well.
4. The code hits the `if (!provider || !model)` check, shows a toast (which might be missed or hidden), and **returns early without making any network request**.

### Recommended Fix:

1. **Explicitly set `shouldUnregister: false`** in the `useForm` call within `AgentPanel.tsx` to ensure that values from unmounted panels are preserved.
2. **Use `getValues()`** for critical fields like `id`, `provider`, and `model` within `onSubmit` to ensure you are getting the most up-to-date values from the form's internal state, regardless of whether they are currently mounted.

```typescript
// client/src/components/SidePanel/Agents/AgentPanel.tsx

// 1. Update useForm configuration
const methods = useForm<AgentForm>({
  defaultValues: getDefaultAgentFormValues(),
  mode: 'onChange',
  shouldUnregister: false, // Ensure values persist across panel switches
});

// 2. Use getValues in onSubmit for critical fields
const onSubmit = useCallback(
  async (data: AgentForm) => {
    // ... tools logic ...
    
    // Instead of relying on scoped agent_id from useWatch, which might be stale or undefined
    const currentId = getValues('id');
    const { payload: basePayload, provider, model } = composeAgentUpdatePayload(data, currentId);

    if (currentId) {
       // ... update logic ...
       update.mutate({ agent_id: currentId, data: { ...basePayload, tools } });
       return;
    }
    // ...
  },
  [getValues, ...otherDeps]
);
```

Additionally, ensure `composeAgentUpdatePayload` has a safety check for when `provider` is an object but potentially `null` or missing the `value` property, as `(data.provider as StringOption).value` will throw a runtime error if `data.provider` is `undefined`, preventing the mutation from ever being called.
